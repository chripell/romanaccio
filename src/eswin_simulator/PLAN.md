# Open EsSimulator (`eswin_simulator`) Implementation Plan

## 1. Project Overview & Objectives

The goal of `eswin_simulator` is to provide a bit-accurate, platform-independent, open-source functional simulator capable of executing ESWIN `.model` offline loadables without requiring physical RISC-V hardware (`roma`).

### 1.1 Goals
- Replace the 32-bit x86-only proprietary `EsSimulator` binary with a clean, 64-bit cross-platform execution engine.
- Execute both NPU hardware submodels (NVDLA-derived CMAC, SDP, PDP, RUBIK, BDMA) and Cadence Vision Q7 DSP kernel submodels.
- Provide bit-accurate numerical verification against PyTorch and ONNX golden data tensors.
- Offer automated differential analysis: cosine distance, maximum absolute difference, relative error, and layer-by-layer tensor dumping.
- Serve as the automated validation testbed in continuous integration (CI) for models generated by `eswin_compiler`.

### 1.2 Non-Goals
- Cycle-accurate silicon timing simulation (this is a functional and numerical bit-accurate simulator, not an RTL cycle simulator).
- Emulating the physical SiFive E31 microcontroller firmware (commands are parsed directly from the submodel descriptor stream).

## 2. Programming Language Evaluation & Selection

### Options Considered
- **C++ (SystemC / NVDLA cmod)**: NVIDIA's open-source `NV_NVDLA_cmod` is written in C++ with SystemC and Algorithmic C (`ac_int`, `ac_channel`). While accurate, building and maintaining SystemC across modern Linux distributions introduces significant compilation overhead and rigid debugging constraints.
- **Python (Selected Core) with Native C Acceleration**:
  - **Core Simulation & Orchestration in Python**: High-level loadable parsing, tensor memory management, numerical verification, and differential testing are dramatically easier to build, debug, and script in Python with `numpy` and `scipy`.
  - **Bit-Accurate Numerics in NumPy**: NumPy natively supports IEEE 754 half-precision float (`np.float16`), signed 8-bit integers (`np.int8`), and 32-bit accumulation (`np.int32`).
  - **DSP Kernel Execution**: Python's `ctypes` dynamically binds and invokes existing host-compiled DSP kernel shared libraries (`dsp_kernels/libes_*.so`) with zero overhead, while offering pure-Python mathematical fallbacks for unsupported platforms.
  - **Native C Helper**: A minimal C extension (`es_accel.c`) for hot convolution loops if needed, though NumPy vectorization is sufficient for functional verification.

### Choice: Python 3.10+ (NumPy + ctypes) + Optional C Fallback Kernels
- **Type Annotations**: Comprehensive typing across all engine interfaces.
- **Extensive Comments**: Every engine's numerical behavior (rounding modes, saturation, clamp bounds, LUT interpolation) will be extensively documented with references to NVDLA and Cadence DSP specifications.

## 4. Incremental Step-by-Step Implementation Roadmap

Development is structured into **6 small, independently verifiable milestones**:

### Milestone 1: Model Loader & Virtual Address Space [COMPLETED]
- **Status**: **Completed & Verified** (9/9 unit tests passing in pytest).
- **Scope Implemented**:
  - `loader/loadable_reader.py`: Reads and parses FlatBuffers `.model` containers with `NVDA` magic verification, extracting memory lists, address tables, tensor descriptors, task partitions, and embedded blobs.
  - `loader/tensor_desc.py`: Rich dataclass representing 4D tensor shapes, strides, data types (`HALF`, `INT8`, `FLOAT`), data formats (`NCHW`, `NHWC`), and input/output flags.
  - `memory/address_space.py`: Simulates 64-bit DRAM and the 4 MiB on-chip SPRAM (`SPRAM_CAPACITY_BYTES = 4 * 1024 * 1024`). Auto-populates static weight blobs (`W_0`, tiled weight splits) and command packets into virtual memory. Provides bit-exact `bind_input()` and `read_tensor()`.
  - `memory/buffer_view.py`: Zero-copy NumPy ndarray views over simulated memory buffers.
  - `cli.py`: Interactive `eswin-sim --info -m model.model` CLI supporting detailed terminal tables, verbose memory dumps (`-v`), and machine-readable JSON output (`--json`).
- **Deliverables**:
  - Package `eswin_simulator` configured via `pyproject.toml` and installed via `pip install -e .`.
  - `tests/test_loader.py` & `tests/test_address_space.py`: 9/9 passing tests validating container parsing, tensor descriptors, static weight loading, and buffer boundary protections across `test_conv_npu_b1.model`, `test_swiglu_mlp_npu_b1.model`, and `test_linear_1x1conv_npu_b1.model`.
- **Documentation**:
  - `src/eswin_simulator/README.md`: Quick start guide, CLI options, Python API examples, and test suite instructions.

### Milestone 2: Memory Relocation & BDMA Engine [COMPLETED]
- **Status**: **Completed & Verified** (14/14 unit tests passing in pytest).
- **Scope Implemented**:
  - `memory/address_space.py`:
    - Dynamic relocation resolver parsing `RelocEntry` records: patches 64-bit IOVA addresses (splitting into lower and upper 32-bit little-endian words via `reloc_type` 1 and 2) directly into command/surface descriptors.
    - 64-bit virtual memory address translation: `read_vaddr_bytes()` and `write_vaddr_bytes()` with automatic DRAM / SPRAM region detection.
    - Tensor binary file I/O: `load_input_file()` and `dump_output_file()` with multi-file loading (`load_inputs()`, `dump_outputs()`).
  - `engines/base_engine.py`: Abstract `HardwareEngine` base class for all accelerator sub-engines.
  - `engines/bdma.py`: Full Bridge DMA simulation engine supporting 1D contiguous transfers, 2D pitch-strided matrix copies, and 3D planar volume transfers between DRAM and on-chip 4 MiB SPRAM.
  - `cli.py`: Updated CLI supporting `--input <ifmap.bin>` and `--output <ofmap.bin>` execution modes matching vendor `EsSimulator` syntax.
- **Deliverables**:
  - Extended `VirtualAddressSpace`, `BDMAEngine`, and `cli.py`.
  - `tests/test_bdma.py`: 5 comprehensive tests validating relocation bit-accuracy, 1D/2D/3D strided BDMA transfers, and tensor binary file round-trip I/O.
- **Documentation**:
  - Mathematical description of BDMA surface stride and line stride calculations in `src/eswin_simulator/README.md`.

### Milestone 3: NPU Convolution & GEMM Functional Engine (CMAC + CACC) [COMPLETED]
- **Scope**:
  - Implement `engines/cmac.py` and `engines/cacc.py`.
  - Simulate 2D convolution and $1\times 1$ pointwise Conv (GEMM) for both **FP16** and **INT8** precisions:
    - FP16 mode: IEEE 754 half-precision multiplication with FP32 accumulator.
    - INT8 mode: 8-bit signed multiplication with 32-bit signed accumulator (`int32_t`), channel scale application, and clipping to $[-128, 127]$.
  - Support dilation, stride, padding, and grouped/depthwise configurations.
- **Deliverables**:
  - `engines/cmac.py`: `CMACEngine` supporting 2D spatial convolution, grouped/depthwise convolution, 1x1 GEMM matrix multiplications, and NVDLA weight de-tiling (`unpack_nvdla_weights_conv2d`, `unpack_nvdla_weights_1x1`).
  - `engines/cacc.py`: `CACCEngine` supporting 32-bit accumulation, FP16 rounding, and strict INT8 saturating clipping to $[-128, 127]$.
  - CLI `eswin-sim` extended with `--compare` differential testing mode.
- **Testing Requirements**:
  - `tests/test_cmac_cacc.py`: 7 comprehensive tests covering FP16, bit-exact INT8 integer parity, depthwise convolutions, GEMM tensor shapes, and CACC saturation.
  - Differential testing against vendor `EsSimulator`:
    - `test_conv_npu_b1.model`: Cosine Similarity $= \mathbf{1.000000}$, Relative Diff $= \mathbf{0.000000}$.
    - `test_linear_1x1conv_npu_b1.model`: Cosine Similarity $= \mathbf{1.000000}$, Relative Diff $= \mathbf{0.000518}$.
- **Documentation**:
  - Mathematical specification of NVDLA weight de-tiling and CACC saturating clipping in `README.md`.

### Milestone 4: Single Data Point Engine (SDP) & Non-Linear LUTs [COMPLETED]
- **Scope**:
  - Implement `engines/sdp.py`:
    - Standalone and fused bias addition with broadcasting.
    - ReLU, LeakyReLU, and PReLU.
    - Piecewise linear activation LUT (256/512 entries) for Sigmoid and SiLU/Swish.
    - Elementwise operations: tensor addition, subtraction, multiplication, min, max.
    - Precision conversion (FP16 $\to$ INT8 with scaling, INT8 $\to$ FP16).
- **Deliverables**:
  - `engines/sdp.py`: `SDPEngine` and `SDPLookupTable` supporting all fixed-function activations, arbitrary piecewise linear LUTs, pointwise ALU ops, and precision casting.
  - End-to-end multi-op pipeline in `cli.py` for SwiGLU MLP blocks.
- **Testing Requirements**:
  - `tests/test_sdp.py`: 7 tests verifying bias addition, batchnorm, activations, elementwise ALU, and piecewise linear LUT interpolation.
  - Differential verification against vendor `EsSimulator`:
    - `test_swiglu_mlp_npu_b1.model`: Cosine Similarity $= \mathbf{1.000000}$ ($0.99999976$), Max Absolute Diff $= \mathbf{0.000244}$.
- **Documentation**:

### Milestone 5: DSP Submodel Execution Engine (ctypes & Native Fallbacks) [COMPLETED]
- **Scope**:
  - Implement `dsp/dsp_executor.py`:
    - Simulates Cadence Vision Q7 DSP cluster execution environment.
    - Defines Cadence Vision Q7 DSP C ABI structures (`struct es_dsp_buffer_t`, `struct es_dsp_buffer_group_t`).
    - Dynamic loader for vendor `dsp_kernels/*.so` when executed in compatible environments.
  - Implement `dsp/native_fallbacks/`:
    - Pure NumPy bit-accurate implementations of `RMSNorm`, `Softmax`, `RoPE`, and `TopK`.
    - Cross-platform 64-bit native fallbacks (x86_64, aarch64, riscv64) overcoming 32-bit vendor shared library architectural limits.
- **Deliverables**:
  - `dsp/dsp_executor.py`: `DSPExecutor` engine tracking lifecycle, operation metrics, and memory routing.
  - `dsp/native_fallbacks/rms_norm.py`: Bit-accurate RMSNorm supporting FP16/FP32 and INT8 quantization with output scaling and clipping.
  - `dsp/native_fallbacks/softmax.py`: Numerically stable Softmax with online max-subtraction preventing exponential overflow.
  - `dsp/native_fallbacks/rope.py`: Rotary Position Embedding supporting both Hugging Face `half` mode and Cadence DSP `interleaved` pair mode, strictly preserving unitary L2 norm.
  - `dsp/native_fallbacks/topk.py`: Top-K value and index extraction with $O(N)$ partitioning.
- **Testing Requirements**:

    - `Softmax` across axes (-1, 1, 0) and extreme numerical stability tests ($x \ge 1000.0$) against PyTorch `F.softmax`.
    - `RoPE` differential parity against Hugging Face reference implementation ($< 1.4 \times 10^{-6}$) and unitary norm preservation.
    - `TopK` bit-exact index and value parity against `torch.topk`.
- **Documentation**:
  - DSP C ABI specification and native fallback API documentation in `README.md`.

## 5. Coding Standards & Numerical Guarantees

1. **IEEE 754 Parity**: Half-precision floating-point arithmetic must strictly emulate IEEE 754 FP16 (including subnormals, infinities, and NaN handling).
2. **Saturating Arithmetic**: Signed 8-bit operations must strictly saturate at $[-128, 127]$ rather than wrapping around.
3. **Reproducibility**: Simulations must be 100% deterministic on all host platforms.
