# ESWIN EIC7700X `.model` Loadable Format Specification

## 1. Overview & Binary Container

The `.model` offline loadable is the compilation artifact generated by `EsAAC` (and our open `eswin_compiler`) and consumed by both `EsSimulator` and `libnn_runtime.so` / `libedla_runtime.so`. 

- **Container Technology**: Google FlatBuffers binary serialization format (version 2.0.0).
- **Magic Identifier**: `"NVDA"` at byte offset `0x04` to `0x07` (derived from NVIDIA NVDLA `ILoadable` container format, customized by ESWIN for EIC7700X dual-die NPU & DSP engines).
- **Byte Order**: Little-Endian (LSB first), 32-bit offset pointers.
- **Root Table**: Table `Loadable` located at root offset pointed by bytes 0..3.

### Binary Header Layout
```
Offset  Size (bytes)   Description
0x00    4              Offset to Root Table (FlatBuffers uoffset_t, little-endian)
0x04    4              File Identifier: ASCII "NVDA" (0x4E 0x56 0x44 0x41)
0x08    ...            FlatBuffers vtables, tables, vectors, and raw binary blobs
```

## 3. Detailed Table Semantics

### 3.1 `Loadable` (Root Table)
Contains exactly 9 top-level fields:
1. `version`: Loadable specification version (standard vendor models use `0.7.0`).
2. `task_list`: Sub-models partitions (UMD task graph and KMD hardware tasks).
3. `memory_list`: Memory allocation descriptors (DRAM/SRAM regions, flags, sizes).
4. `address_list`: Virtual address table mapping address IDs to memory allocations and offsets.
5. `event_list`: Synchronization primitives between tasks.
6. `blobs`: Raw binary blobs for weight tensors, register command packets, and lookup tables.
7. `tensor_desc_list`: User-facing input and output tensor descriptors (shapes, formats, strides).
8. `reloc_list`: IOVA address relocation table (patches buffer DMA addresses into command streams).
9. `submit_list`: Execution queue submission descriptors.

### 3.2 `Blob`
Stores raw binary data:
- Weights: e.g. `W_0`, FP16 or INT8 weights with `interface = 0` (NONE).
- Register Commands:
  - `umd-task-op_list`: High-level operation graph for userspace runtime.
  - `umd-task-surf_list`: Surface/tensor memory descriptors for UMD.
  - `kmd-task-op_list`: Low-level hardware command packets submitted via ioctl to `/dev/npuX`.
  - `kmd-task-surf_list`: Hardware surface descriptors patched by relocations.
  - `kmd-task-config_list`: Hardware engine configuration commands.
  - `kmd-task-lut_list`: Non-linear activation LUT lookup tables.

### 3.3 `RelocListEntry`
When the runtime allocates DMA buffers (`ES_SYS_MemAlloc`), their actual physical/IOVA addresses are unknown at compile time.
The relocation table records each command stream offset where an IOVA address must be written before submission to the kernel:
- `address_id`: Index into `address_list`.
- `write_id`: Target blob index where relocation is applied.
- `offset`: Byte offset inside the target blob.
- `reloc_type`: `1` for lower 32-bit address, `2` for upper 32-bit address.

## 4. Open-Source Python Reader and Writer

Implemented in `src/eswin_compiler/backend/flatbuffer_emitter.py`:
- `ModelReader.read_file(path)` / `ModelReader.read_bytes(buf)`: Parses any `.model` file into high-level dataclasses.
- `ModelWriter.write_file(model, path)` / `ModelWriter.serialize(model)`: Serializes dataclasses back into a valid `.model` FlatBuffers package.
- Full round-trip tested and verified against all vendor sample models in `src/eswin_compiler/tests/test_schema_roundtrip.py`.

## 5. Hardware Execution & Runtime Driver Requirements (Physical Silicon Verification)

During physical silicon validation on the EIC7700X dual-die hardware (`roma`), several critical driver-level constraints were identified and documented:

### 5.1 Blob Versioning Protocol (`libedla_runtime.so`)
The vendor userspace runtime `libedla_runtime.so` parses FlatBuffers blob entries and checks their semantic version fields:
- **Weight Blobs** (`interface = 0`): Must have `version = (0, 0, 0)`.
- **KMD / UMD Task Descriptors** (`interface = 1` or `2`): Must have `version = (0, 0, 3)`.
- If task blobs are stamped with `(0, 7, 0)` (matching the root loadable version), the runtime loader silently fails to parse the task graph, leading to CDMA/BDMA engine hangs waiting indefinitely on uninitialized queues.

### 5.2 4KB Page Alignment for DMA Scratch Buffers
Any system memory region allocated for DMA scratchpads (such as precision conversion buffer `conv1_cvtPrecision` with `flags = 1` / `ALLOC`):
- Must have its allocated byte size rounded up to the nearest 4096-byte page boundary: `size = (raw_bytes + 4095) & ~4095`.
- If unaligned, the kernel memory allocator (`eic7700_npu` driver ioctl `IOCTL_MEM_ALLOC`) fails or causes IOMMU page faults during hardware DMA.

### 5.3 NVDLA CMAC FP16 Weight Tiling
The NVDLA hardware convolution core expects FP16 weights packed into hardware atomic groups rather than standard flat row-major `[C_out, C_in, K_h, K_w]`:
- Output channels are grouped into atomic groups of 8: `c_out_groups = ceil(C_out / 8)`.
- Input channels are aligned to multiples of 4: `c_in_aligned = ceil(C_in / 4) * 4`.
- Memory layout: Padded tensor of shape `(c_out_groups, 8, c_in_aligned, K_h, K_w)` transposed to `(c_out_groups, c_in_aligned, K_h, K_w, 8)`.
- Flattening weights sequentially without this transformation causes hardware CMAC fetch hangs.

### 5.4 Physical Silicon Parity Results (2D Convolution)
A custom 2D convolution model (`test_compiler_e2e.model`) compiled directly from an EIR graph via `eswin_compiler` achieved:
- **Die 0**: 0.18 ms average latency (**5,479 fps** throughput).
- **Die 1**: 1.32 ms average latency (**758 fps** throughput).
- **Numerical Parity**: Verified with `es_run_model -v -t 0.05` reporting **`Cosine similarity compare success!`** against PyTorch golden outputs.

### 5.5 1x1 Pointwise Multi-Pass GEMM Architecture & Verification
Linear projection layers in transformer models (e.g. SmolLM, Gemma, Qwen2 QKV projections and MLP expansions) operate as $1\times 1$ pointwise matrix multiplications:
- **Weight Packing Layout**: FP16 weights are organized into hardware atomic tiles of 8 output channels and 2 input channels:
  $$\text{Shape: } \left(\left\lceil\frac{C_{out}}{8}\right\rceil, \left\lceil\frac{C_{in}}{2}\right\rceil, 8, 2\right)$$
  Transposed from $\left(\left\lceil\frac{C_{out}}{8}\right\rceil, 8, \left\lceil\frac{C_{in}}{2}\right\rceil, 2\right)$.
- **3-Pass SRAM Tiling (`tiling_M_Concat`)**:
  When $C_{out} = 1536$ (e.g. SmolLM MLP expansion / QKV projection), the layer is split into 3 symmetric passes of 512 output channels each ($M_0, M_1, M_2$).
  Each pass:
  1. BDMA transfers weight slice ($589,824$ bytes) from DRAM to on-chip SPRAM.
  2. CDMA streams activation input ($C_{in} = 576$, 1152 bytes) and weights from SPRAM into CMAC.
  3. SDP accumulates and writes the 1024-byte output slice to offset $p \times 1024$ in the concatenated output buffer.
- **Physical Silicon Verification**:
  Synthesized and compiled an end-to-end 3-pass GEMM model (`test_compiler_gemm_e2e.model`, 1.8 MB) with random weights directly using `NVDLAGEMMBuilder`.
  - **Die 0**: Average latency **0.24 ms** (**4,120 fps** throughput).
  - **Die 1**: Average latency **1.20 ms** (**833 fps** throughput).
  - **Numerical Parity**: Tested with `es_run_model -v -t 0.05` reporting **`Cosine similarity compare success!`** against golden PyTorch outputs.
